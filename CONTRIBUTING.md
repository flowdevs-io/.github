# Contributing to FlowDevs repositories

Thanks for taking the time. These are the defaults for repositories in [flowdevs-io](https://github.com/flowdevs-io) that do not ship their own contributing guide.

## Before you start

- Read the [engineering standards](https://github.com/flowdevs-io/.github/blob/main/docs/engineering-standards.md).
- For security issues, follow [SECURITY.md](https://github.com/flowdevs-io/.github/blob/main/SECURITY.md). Do not file a public issue.

## Issues

Use the bug or feature templates when they fit. Say what you observed, what you expected, and how to reproduce. Skip customer names, tokens, and private URLs.

## Pull requests

Shared FlowDevs repositories take changes through pull requests — do not push straight to the default branch.

Use the pull request template:

1. **What and why** — what changed and why it is needed
2. **Risk** — what could break
3. **Test plan** — how you verified it
4. **Rollback** — how to undo it

Keep the diff scoped. Do not commit secrets, credentials, or customer data.

Individual repos may add extra review, CI, or branch rules. Follow those when they exist.
